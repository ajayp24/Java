2. Mockito

@ExtendWith(MockitoExtension.class) class OrderServiceTest { @Mock OrderRepository repo; @Mock PaymentService payment; @InjectMocks OrderService service; // injects mocks via constructor or field @Test void placeOrderSuccessfully() { // Arrange — stub dependencies var order = new Order(1L, OrderStatus.PENDING); Mockito.when(repo.save(Mockito.any(Order.class))).thenReturn(order); Mockito.when(payment.charge(Mockito.any(), Mockito.any())).thenReturn(PaymentResult.ok()); // Act var result = service.placeOrder(new CreateOrderRequest(...)); // Assert Assertions.assertEquals(OrderStatus.PENDING, result.getStatus()); // Verify interactions Mockito.verify(repo, Mockito.times(1)).save(Mockito.any(Order.class)); Mockito.verify(payment).charge(Mockito.any(), Mockito.any()); Mockito.verifyNoMoreInteractions(repo, payment); } @Test void capturesSavedOrder() { // ArgumentCaptor — capture what was passed to a mock ArgumentCaptor<Order> captor = ArgumentCaptor.forClass(Order.class); service.placeOrder(req); Mockito.verify(repo).save(captor.capture()); Assertions.assertEquals(OrderStatus.PENDING, captor.getValue().getStatus()); } @Test void propagatesPaymentFailure() { // Stub to throw exception Mockito.when(payment.charge(Mockito.any(), Mockito.any())) .thenThrow(new PaymentDeclinedException("Insufficient funds")); Assertions.assertThrows(OrderCreationException.class, () -> service.placeOrder(req)); } }

REFACTOR — clean up code; test still passes // RED: write test first @Test void discountAppliedForMembersOver50() { var pricer = new OrderPricer(); var order = Order.withTotal(BigDecimal.valueOf(100)); var member = Member.premium(); Assertions.assertEquals( BigDecimal.valueOf(90), // expected 10% off pricer.calculateFinalPrice(order, member) ); } // GREEN: minimal implementation public BigDecimal calculateFinalPrice(Order order, Member member) { if (member.isPremium() && order.getTotal().compareTo(BigDecimal.valueOf(50)) >= 0) { return order.getTotal().multiply(BigDecimal.valueOf(0.9)); } return order.getTotal(); } // REFACTOR: extract discount rate to constant, add more test cases

6. Test Pyramid

LayerCountSpeedToolsWhat to test
Unit testsMost (~70%)MillisecondsJUnit 5, MockitoBusiness logic, edge cases, algorithms
Integration testsMedium (~20%)Seconds@SpringBootTest, TestcontainersDB queries, API clients, message consumers
E2E testsFew (~10%)MinutesSelenium, Playwright, CucumberCritical user journeys end-to-end
The "ice cream cone" anti-pattern is the inverse — many slow E2E tests, few unit tests. This leads to slow feedback loops and fragile test suites. Prioritize fast unit tests for logic and use integration tests for contract verification.

7. Interview Q&A

When would you use @MockBean vs @Mock in Spring Boot tests?
@Mock (Mockito) — creates a mock outside the Spring context. Use in pure unit tests that don't load any Spring beans. Works with @ExtendWith(MockitoExtension.class). Fast, no Spring overhead.

@MockBean (Spring Boot Test) — creates a Mockito mock AND registers it as a Spring bean, replacing the real bean in the ApplicationContext. Use when the class under test needs the Spring context (e.g., @WebMvcTest for controllers). Slower because Spring context loads.

Rule of thumb: prefer @Mock + @InjectMocks for service-layer unit tests. Use @MockBean only when you need the Spring context (controller slice tests, JPA slice tests).
What is the difference between a stub, mock, and spy?
Stub — provides canned answers to calls. No verification. Used to control dependencies' behavior.

Mock — a stub that also records interactions so you can verify them later (mockito.verify()). Fails if unexpected calls occur when using strict mode.

Spy — wraps a real object. Real methods are called unless explicitly stubbed. Use Mockito.spy(realObject) or @Spy. Useful when you want real behavior for most methods but stub specific ones.

Example: a Spy on an ArrayList — add() and get() really work, but you can stub size() to return a fixed value and verify that add() was called.
How do you test code that depends on the current time?
Never use LocalDate.now(), Instant.now(), or System.currentTimeMillis() directly in production code that needs to be tested — they can't be controlled in tests.

Fix — inject Clock:
Production: inject a fixed Clock or system Clock via DI.
Test: inject Clock.fixed(expectedInstant, ZoneOffset.UTC).

Example: public class OrderService { private final Clock clock; ... LocalDate.now(clock); }
In test: new OrderService(Clock.fixed(Instant.parse("2024-01-15T00:00:00Z"), ZoneOffset.UTC))

This eliminates flakiness from time-dependent logic (expiry, scheduling, age calculations).
